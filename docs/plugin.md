# Plugin reference

The `llm-docs` plugin for Claude Code and Cursor lives in [`plugin/`](../plugin). [The plugin README](../plugin/README.md) covers installing it, what the session-start note says, how to turn it off, and what it sends over the network. This page is the reference for the parts that README leaves out: the hook's exact behavior and budgets, which agent files each harness reads, and troubleshooting.

## What it installs

| Path | What it is |
|---|---|
| `hooks/hooks.json` | The Claude Code hook: `SessionStart` with matcher `startup\|resume\|clear\|compact\|fork`, timeout 5 s, running `node "${CLAUDE_PLUGIN_ROOT}/bin/llm-docs.mjs" hook session-start`. |
| `hooks/cursor-hooks.json` | The Cursor hook: `sessionStart`, timeout 5 s, running `node ./bin/llm-docs.mjs hook session-start` from the plugin root. |
| `bin/llm-docs.mjs` | The whole CLI bundled into one file, generated by `npm run build:plugin` and committed. |
| `bin/llm-docs`, `bin/llm-docs.cmd` | POSIX and Windows wrappers for the bundle. Claude Code puts `bin/` on the agent's shell `PATH`. |
| [`skills/add-docs`](../plugin/skills/add-docs/SKILL.md) | How the agent plans and builds a pack. |
| [`skills/write-docs-guide`](../plugin/skills/write-docs-guide/SKILL.md) | How the agent writes, fact-checks, and stamps a guide. |
| [`skills/llm-docs`](../plugin/skills/llm-docs/SKILL.md) | The command reference the agent reads. |
| [`agents/docs-fact-checker.md`](../plugin/agents/docs-fact-checker.md) | Checks each claim in a guide against the pages it cites. |

The marketplaces are `.claude-plugin/marketplace.json` (plugin source `./plugin`) and `.cursor-plugin/marketplace.json` (plugin source `plugin`) at the repository root. Plugin and marketplace versions equal the package version; `npm run check:plugin` fails when they or the bundle are out of date.

## The session-start hook

`llm-docs hook session-start` reads the harness's JSON payload on stdin and prints the note for the agent. `llm-docs status --brief` prints the same text for the current project, so you can preview it.

### Harness detection

| Condition | Harness | Output shape |
|---|---|---|
| `CURSOR_VERSION` or `CURSOR_PLUGIN_ROOT` is set | Cursor | `{"additional_context": "..."}` |
| `CLAUDECODE=1` | Claude Code | `{"hookSpecificOutput": {"hookEventName": "SessionStart", "additionalContext": "..."}}` |
| Anything else, Codex included | unknown | The Claude Code shape |

### Project

The hook starts from the payload's `cwd`, else `CLAUDE_PROJECT_DIR`, else Cursor's `workspace_roots[0]`, else the process working directory, and then finds the project root as every command does. With no `llm-docs.json` it still runs the dependency analysis, so a project gets the note about new dependencies before it pins any docs.

A payload that is not JSON, is over 1 MiB, or is still arriving after the read budget is logged and ignored, and these fallbacks apply.

### Model and cutoff

The model id comes from the first of:

1. The payload's `model` (Claude Code sends it in some sessions; headless `-p` runs leave it out). Cursor's `model_id` or `model`.
2. `ANTHROPIC_MODEL`.
3. `model` in `<project>/.claude/settings.local.json`, then `<project>/.claude/settings.json`, then `~/.claude/settings.json`.

Claude Code aliases (`opus`, `sonnet`, `haiku`, `fable`, with an optional suffix such as `[1m]`) resolve to the model the alias currently selects, through the table in [`data/model-cutoffs.json`](../data/model-cutoffs.json). A pin variable such as `ANTHROPIC_DEFAULT_OPUS_MODEL` wins, and `CLAUDE_CODE_USE_BEDROCK`, `CLAUDE_CODE_USE_VERTEX`, and `CLAUDE_CODE_USE_FOUNDRY` select that provider's alias table.

The cutoff then comes from `model.cutoff` in `llm-docs.json`, `LLM_DOCS_MODEL_CUTOFF`, or the table entry for the model id, in that order. The table lists only models whose cutoff has a published source, and records that source per entry. With no cutoff, the note lists releases from the last 180 days under a neutral heading instead of guessing.

### Content and budget

The note has up to four parts, described in [the plugin README](../plugin/README.md#what-the-note-says). It is at most 2,000 characters. Over that budget, text is cut from the bottom up: part 4 first, then the rows of the lowest remaining part from its last row. In part 2, the read-first paths are cut before any row. A cut list ends with how many entries it left out and points to `llm-docs status`.

### Time budget

| Budget | Value |
|---|---|
| Whole run, from process start | 1.5 s. A run that misses it prints nothing. |
| Reading the payload | 1 s at most |
| Network lookups for release dates missing from the cache | 1 s, shared by all lookups |
| Background warm-up | At most one detached `llm-docs status` per project every 6 hours, to fetch dates still missing for the next session |

The harness timeout in both hook files is 5 s, well above the hook's own deadline.

### Failure policy

The hook always exits 0, never writes to stderr, and prints nothing when it fails. A malformed `LLM_DOCS_MODEL_CUTOFF` does not fail it: the hook logs the value, ignores it, and takes the cutoff from the next source, or uses the neutral heading when none is left. A malformed `model.cutoff` makes `llm-docs.json` invalid, and with an invalid config the hook logs the problem and sends only the dependency part of the note. It logs problems to `hook.log` in the cache directory, which rotates at 1 MB and keeps one previous file, `hook.log.1`. If `node` is not on the `PATH` the harness passes to hooks, the hook command fails and both harnesses treat that as a non-blocking error.

## Which agent files each harness reads

`llm-docs sync` writes the managed block into the files `agentFiles` names (see [`agentFiles`](config.md#agentfiles)). Whether a session sees that block depends on the harness:

| Harness | Reads |
|---|---|
| Codex | `AGENTS.md` |
| Cursor | `AGENTS.md` |
| Claude Code | `CLAUDE.md` and `CLAUDE.local.md`. It reads `AGENTS.md` only when no `CLAUDE.md` or `CLAUDE.local.md` exists in the project root or any directory above it, unless one of the project's own files imports `@AGENTS.md`. |

So a `CLAUDE.md` in a parent directory hides the block in the project's `AGENTS.md` from Claude Code. When packs exist and the file this harness reads has no block, the hook adds the pack list to the note itself (part 4). A harness the hook cannot identify is assumed not to see the block. The same applies to a project that keeps `AGENTS.md` out of git.

## Configuration and environment

| Setting | Effect |
|---|---|
| `"hook": { "enabled": false }` in `llm-docs.json` | No note for this project. |
| `"hook": { "nearCutoffDays": N }` | How many days before the cutoff count as near it. Default 90. |
| `"model": { "cutoff": "YYYY-MM" }` | Fixes the cutoff for this project. |
| `LLM_DOCS_HOOK=off` | No note anywhere. |
| `LLM_DOCS_MODEL_CUTOFF=YYYY-MM` | The cutoff when the config sets none. |
| `LLM_DOCS_CACHE_DIR` | Moves the cache directory, which holds `release-dates.json`, `hook.log`, and `hook-warm/`. |
| `GITHUB_TOKEN` | Sent to `api.github.com` for Swift package release dates. |

## Troubleshooting

To see what a session would get, run `llm-docs status --brief` in the project. Add `--model <id>` or `--cutoff YYYY-MM` to try another model. An empty result means there is nothing to say: no pack needs a rebuild, and no dependency is newer than the cutoff or near it.

If the note is missing in a session but `status --brief` prints text:

1. Read `hook.log` in the cache directory. Without `LLM_DOCS_CACHE_DIR` or `XDG_CACHE_HOME`, it is `~/Library/Caches/llm-docs/hook.log` on macOS, `%LOCALAPPDATA%\llm-docs\Cache\hook.log` on Windows, and `~/.cache/llm-docs/hook.log` elsewhere.
2. Check that `node` 22.19 or newer is on the `PATH` your editor passes to hooks.
3. Check that the release dates are cached. A first session can miss its 1.5 s deadline while it looks dates up; the background warm-up fills the cache for the next one. Running `llm-docs status` once fills it too.
4. Check `LLM_DOCS_HOOK` and `hook.enabled`.

If the note names the wrong cutoff, set `model.cutoff` in `llm-docs.json` or `LLM_DOCS_MODEL_CUTOFF`. The heading of parts 2 and 3 names the cutoff and where it came from.
